# Безкоштовне тестування MagnitApp на Render.com

Ця інструкція — для **перевірки, чи все працює** (продаж, камера, push-
сповіщення), без жодних витрат. Для щоденної реальної роботи 4 точок
варто перейти на платний VPS (~$70-80/рік) — Render безкоштовно "засинає"
і скидає базу даних при кожному перезапуску (див. застереження внизу).

## Крок 1: Викласти код на GitHub

Якщо ще не маєте акаунту GitHub — зареєструйтесь на github.com (безкоштовно).

```bash
cd magnitapp
git init
git add .
git commit -m "MagnitApp"
```

Потім на github.com натисніть **New repository**, назвіть, наприклад,
`magnitapp`, і виконайте команди, які GitHub покаже на екрані після
створення (приблизно такі):

```bash
git remote add origin https://github.com/ВАШ_ЛОГІН/magnitapp.git
git branch -M main
git push -u origin main
```

## Крок 2: Створити акаунт Render

1. Зайдіть на **render.com** → **Get Started** → увійдіть через GitHub
   (картка не потрібна для безкоштовного тарифу)

## Крок 3: Розгортання одним кліком (Blueprint)

У цьому архіві вже є готовий файл `render.yaml`, який налаштовує все
автоматично:

1. На Render: **New** → **Blueprint**
2. Оберіть репозиторій `magnitapp`, який щойно завантажили
3. Render сам знайде `render.yaml` і запропонує створити сервіс
4. Він попросить ввести два значення:
   - `HEAD_ADMIN_USERNAME` — логін головного адміна, наприклад `admin`
   - `HEAD_ADMIN_PASSWORD` — надійний пароль
5. Натисніть **Apply** — Render почне збірку (2-5 хвилин)

## Крок 4: Відкрити застосунок

Після завершення збірки Render покаже адресу типу:
```
https://magnitapp-xxxx.onrender.com
```

Відкрийте її в браузері телефону — це вже готовий HTTPS, можна одразу
"Додати на головний екран". Увійдіть логіном/паролем головного адміна.

## Якщо розгортання Blueprint не спрацювало (запасний варіант вручну)

1. **New** → **Web Service** → підключіть репозиторій
2. **Root Directory**: `backend`
3. **Build Command**: `pip install -r requirements.txt`
4. **Start Command**: `gunicorn app:app --timeout 120 --workers 2 --threads 2`
5. **Instance Type**: Free
6. У розділі **Environment** додайте змінні:
   - `JWT_SECRET` = будь-який довгий випадковий рядок
   - `HEAD_ADMIN_USERNAME` = `admin`
   - `HEAD_ADMIN_PASSWORD` = ваш пароль
7. **Create Web Service**

## ⚠️ Важливі застереження безкоштовного тестування

0. **Обробка фото на безкоштовному тарифі помітно повільніша**, ніж на
   реальному сервері — тариф Free дає лише **0.1 CPU** (дуже слабко).
   Ми стиснули фото прямо в браузері перед відправкою і виправили
   налаштування запуску сервера, щоб він не обривав довгі запити і міг
   обробляти кілька дій одночасно - це має суттєво прискорити роботу.
   Але навіть після цього обробка фото на Free-тарифі лишається
   повільнішою за звичайний комп'ютер - це обмеження самого тарифу, а
   не помилка застосунку. Якщо швидкість критична вже зараз - варто
   одразу дивитись у бік платного тарифу Starter ($7/міс, 0.5 CPU).

1. **База даних скидається** при кожному перезапуску/повторному
   розгортанні сервісу (безкоштовний Render не зберігає диск між
   перезапусками). Для короткого тесту в один присід це не завадить —
   дані живуть, поки сервіс не перезапускається. Але не розраховуйте на
   збереження товарів/продажів між днями на безкоштовному тарифі.

2. **"Засинання" після 15 хв бездіяльності** — перший запит після паузи
   виконується до ~1 хвилини (сервіс "прокидається"). Це нормально для
   тесту, незручно для щоденної роботи.

3. **Штрихкоди можуть не розпізнаватись** — якщо Render не встановить
   системну бібліотеку `libzbar0` (потрібну для читання штрихкодів),
   застосунок все одно запуститься і працюватиме (продаж, звіти, все
   інше) — просто розпізнавання за штрихкодом буде вимкнене, а пошук за
   схожістю фото продовжить працювати нормально.

## Коли переходити на платний VPS

Як тільки перевірили, що все влаштовує — переносите на VPS з README.md
в корені архіву: та сама структура коду, просто `python3 app.py` замість
`gunicorn`, і дані вже зберігаються постійно.
